Who does what

Each person owns one layer and one shared job. The brain (LLM) layer is the hardest, so its owner also handles integration. The world layer is the lightest, so its owner also runs testing and the demo.

Siddh · Memory

Declarative layer

What the robot believes, and where each belief came from.

declarative.pydata/default_map.json
Builds
  • Belief graph in NetworkX
  • SQLite log: source, time, confidence for every change
  • query_beliefs, update_belief, get_provenance
  • Conflict rule: live sensor > other bot's log > old map
  • Viewpoint tags (user / self / map / bot_02) for Scenario B
Shared job
  • Leads the final report
Rudraksh · Brain

Procedural layer

The LLM that thinks, calls tools, and answers.

procedural.pytools.pyprompts/
Builds
  • Groq API setup (Llama-3-8B, plus a larger model to compare)
  • ReAct loop: think → call tool → read result → answer
  • Tool definitions the LLM can call
  • System prompt, retries on bad tool calls
  • Step-by-step trace logging
Shared job
  • Integration lead: merges code, keeps main working
Udit · World & tests

sensorimotor.pyscenarios/tests/

  • Mock world: grid, obstacles, objects, lighting

  • Scenario files (the project's "data")
  • Test runner: 5 runs per test, pass rates, saved logs
  • Demo UI (Streamlit, after mid-sem)
Shared job
  • Owns the slides and the demo clip

Rules for working together

Dummies first

On day one, everyone writes fake versions of their functions that return hardcoded data. Nobody waits on anyone else.

schemas.py changes together

It is the one shared file. Tell the group before changing it.

Own branches, reviewed merges

Work on your own branch. Someone else reviews before it goes into main. main must always run.

Daily check-in

Until mid-sem, one short message a day: done, doing next, blocked on.

Everyone writes tests

Each person designs at least 3 of the 10 test scenarios for their own layer.

Know every layer

Evaluators may ask anyone about any part, so explain your layer to the others.
